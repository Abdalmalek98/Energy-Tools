# Decisions

1. **Monorepo with npm workspaces**, TypeScript strict, Vitest, ESLint. One `shared` package so app and service can't drift on the JSON schema.
2. **Service on Cloudflare Workers + D1 + Hono** as briefed. Needs the **Workers Paid plan (~US$5/mo)**: the free plan's 10 ms CPU limit is too tight for parsing ~12 MB image payloads and verifying signatures. Same API can be ported to any host.
3. **Leases**: EdDSA-signed compact tokens (WebCrypto Ed25519 in the Worker; `node:crypto` verify in Electron main). Private key = Workers Secret `LEASE_PRIVATE_KEY`; public key + service URL injected at build time (Vite `define`).
4. **Server is authoritative**: every `/refresh`, `/read-page`, `/deactivate` checks the DB row, so a lock takes effect on the next call; the app refreshes at launch, every 30 min, and before each page read.
5. **Code format**: 20 Crockford-base32 chars (100 bits) from `crypto.getRandomValues`; stored as SHA-256 + last 5; input normalised (case, I/L→1, O→0, dashes/spaces ignored).
6. **Device ID**: SHA-256(MachineGuid + app salt); MachineGuid read with `reg.exe query` (no native module). Salt is a build constant.
7. **Rate limiting**: D1 fixed-window counters (per IP and per code) rather than the Rate Limiting binding, so behaviour is testable in Miniflare.
8. **Admin auth**: password (PBKDF2/scrypt-style hash stored as secret) + TOTP (RFC 6238, replay-protected), 8 h HttpOnly SameSite=Strict cookie, lockout after repeated failures, CSRF token on mutations. CLI uses a separate API key (hash stored as secret).
9. **Quota** counts one page per successful `/read-page`; monthly window = UTC calendar month; refunded on upstream failure.
10. **Model names** are Worker vars (`MODEL_BEST=claude-opus-5-5`, `MODEL_FAST=claude-sonnet-5-5`); the API key never reaches the client.
11. **Auto-update**: `electron-updater` with GitHub Releases (a public releases-only repo). Installers are useless without a licence code, so public hosting is acceptable; avoids R2 cost/complexity. Portable zip is manual-update.
12. **Renderer**: React + Vite; pdf.js and ExcelJS bundled; CSP `default-src 'self'; connect-src` limited to the service origin only in main process (renderer has no network; all HTTP in main via preload IPC).
13. **Arabic/RTL**: cells use `dir="auto"` + `unicode-bidi: plaintext`; file paths handled as UTF-8 throughout.
14. **Post-processing lives only in `shared`** and is pure/deterministic; raw model output is stored in the project so rules can be re-applied without spending pages.
15. **Signing**: electron-builder config reads `CSC_LINK`/`CSC_KEY_PASSWORD` if present; unsigned builds work and trigger SmartScreen (documented in USER_GUIDE).
16. **Lease expiry is client-side grace only.** The server verifies the lease *signature* and then trusts the database (lock, expiry, device binding) on every `/refresh`, `/read-page`, `/deactivate`; an expired lease can therefore still refresh when the PC comes back online.
17. **Upstream errors carry `retryable`** (true for 429/529/5xx/network, false for invalid model output) so the app knows when to back off automatically and when to show "Try again". A page reserved against the quota is refunded on any upstream failure.
18. **Quota reservation is one atomic SQL upsert** (`pages < quota`), so parallel reads can't overshoot the monthly limit.
19. **Prompt ported from the prototype** (`shared/src/prompt.ts`, `vocab.ts`): same structure and per-field rules, with client/country/facility/surveyor names and hospital-only hints removed, plus the brief's extra conventions (section changes, copy notes, stacked values, more ditto forms).
20. **Admin secrets are generated by `npm run setup-secrets`** and never written to disk; the admin page has no external resources and builds DOM with `textContent` only.
21. **The tool is facility-agnostic.** No facility, building or template-specific value is hard-coded anywhere. Al Raith and the five health-centre PDFs are *test fixtures*, not special cases; a unit test asserts the prompt contains no hospital-only vocabulary or facility names.
    - Building name is a per-file setting entered by the user (defaulting to what the model reads in the header).
    - **Context hint**: optional free-text per project (e.g. "Primary school, Arabic room names"), sent as `hint` to `/v1/read-page`, capped at 500 chars, flattened, and passed as user-turn *data* — it cannot alter the system prompt or output format.
    - **Space types** (Phase 2): the editable keyword table is seeded with the brief's mapping **plus** generic sets for education (CLASS/LAB/LIBRARY → CLASSROOM…), commercial (SHOP/SHOWROOM/RECEPTION), industrial (WORKSHOP/FACTORY/HANGAR), religious, residential and outdoor; unmatched rooms fall through to `OTHERS` and are flagged for review rather than guessed.
    - **Accuracy/golden tests** run over every fixture facility, reported per facility, so tuning for one site can't silently hurt others.
22. **Unreadable values are estimated, never left blank, and always highlighted.** The prompt tells the model to estimate and put the field in `uncertain` with an "ESTIMATED" note. As a fallback, the app estimates any blank/`0` value that is required (qty, lamps/fix, watts, unit) or that the model marked uncertain: most common value for the same fixture type in that file, else the row above, else (qty only) 1. Estimates are yellow with an "Estimated: …" cell note and appear in Review Flags. Room names and room sizes are never invented (left blank + flagged).
23. **Blank cells copied from above (light blue)** only apply to the "constant" columns and only when the surveyor was dittoing at least two of them in that row; never to qty, lamps/fix, watts, holder, cut-out, tag or dimensions.
24. **`copy_notes.source_rows`** means the first and last sheet row of the source room's block (inclusive). Expanded rows are inserted right after the block.
25. **Excel writer**: old template data rows are removed by truncating the sheet's row list (ExcelJS `spliceRows` silently keeps them for large counts — caught by the golden test). Dropdowns are rebuilt from clean lists; the template's freeze pane (row 1) and column widths are kept as-is.
26. **Golden test** compares pipeline output with the team's typed answers for one health centre (template rows 3–41), cell by cell; the only allowed differences are cells that are deliberately light-blue (copied) or yellow (estimated), and each is asserted to be highlighted. LibreOffice opens the export and recalculates the Summary formulas to the cached values.
27. **Dates**: the typed answers in the template show Oct/Nov/Dec 2026 for sheets dated e.g. `10-2-26` — apparently read month-first by the typist's Excel. The tool parses day-month-year (setting `DMY`/`MDY`), so the accuracy report must not count that as a reading error.
28. **App architecture**: the renderer has no network and no file-system access. All HTTP (licence + page reading), the encrypted licence store (Electron `safeStorage` = Windows DPAPI), dialogs, `.lsr` files and Excel export live in the main process behind a narrow preload API. The lease token never reaches the renderer.
29. **Offline/lock behaviour**: launch → refresh; every 30 min → refresh; every page read is checked by the server. A service "locked/expired" response locks the UI at once and is *persisted*, so the app stays locked after a restart even offline until an online refresh succeeds. Network failures keep the app usable only until the lease's own expiry (default 72 h); a system clock more than 1 h behind the last server time seen forces an online refresh.
30. **Image pipeline**: page rendered/stored at ≤2600 px JPEG; auto-rotated 90° CCW for portrait scans; the model receives the upright page at ≤2400 px plus top 56 % and bottom 56 % crops, each re-encoded until under ~3.8 MB. Two pages are read in parallel; overloaded/rate-limited responses back off (1.5 s, 5 s, 12 s); invalid model output is never auto-retried.
31. **E2E**: Playwright drives the real Electron build against a mock service that signs leases with a throw-away key baked into the test build (`app/e2e/prepare.mjs`). File dialogs are scripted only in `LSR_E2E` builds run unpackaged. Run with `npm run e2e -w app` (needs xvfb on Linux).
32. **Phase 5 runs on your own machine against a local copy of the real service** (`npm run local`): local D1, your Anthropic key, a code minted for you. The accuracy runner drives the real app so rotation, cropping, the service and post-processing are all in the measurement. It was verified end to end here with a stub upstream (no key available in the build environment); real accuracy numbers come from your run.
33. **Read button waits for files to finish opening** (found by the accuracy harness: pressing Read while a PDF was still rendering read only the pages opened so far).
34. **Packaging**: electron-builder → NSIS one-click **per-user** installer (`LightingSurveyReader-Setup-x.y.z.exe`, no admin rights) and a **portable zip**; ASAR on; the template workbook ships as an extra resource. Authenticode signing is automatic when `CSC_LINK`/`CSC_KEY_PASSWORD` are set; unsigned builds work and show SmartScreen (documented in USER_GUIDE).
35. **Auto-update = GitHub Releases** via `electron-updater` (installed build only; checks ~45 s after launch and every 6 h, installs when the app is closed so it never interrupts a job). Releases live in a separate public repo (`Abdalmalek98/lighting-survey-reader-releases`); a tag `vX.Y.Z` triggers the Windows release workflow.
36. **Release guard** (`app/scripts/release-check.mjs`): a release build is refused unless `LSR_SERVICE_URL` is a real https URL and `LSR_PUBLIC_KEY` is a valid Ed25519 key, and the built bundle is checked for local/placeholder URLs and E2E mode. Found needed because the test build and release build share the same output folder.
37. **Costs are measured, not guessed**: the service logs tokens in/out per page and the admin page/CLI show them, so per-customer cost is computed from the current Anthropic price list.
38. **Licensing redesign (supersedes #2–#5, #8, #9 and the Cloudflare Worker).** Activation codes are signed `LSR1.<payload>.<signature>` (Ed25519, key ids, keyring for rotation) instead of random server-checked codes; the server (Node 22 + `node:sqlite`, VPS + Caddy + systemd) issues signed **receipts** (separate server key, request nonce, offline grace). The Cloudflare Worker, admin CLI and old local-licence tooling were removed (git history keeps them).
39. **Licensing logic is a shared pure library** (`licensing/`) used by the app, the server and the tests, so the real client is tested against the real server and the same status state machine runs everywhere.
40. **Native layer = Electron main process (TypeScript), not Rust.** Stated in SECURITY.md: the local check can be patched by a determined person; the server enforcing every page read is the real protection.
41. **Two licence kinds**: offline (machine-bound, activates with no server contact) and online (server activation + validation). Reading pages always needs the server, so an offline licence registers with the server on its first read; from then on it is revocable. Remote revocation cannot reach a PC that stays offline (documented).
42. **Clock rollback**: licences are judged against the latest time ever seen; offline re-entry cannot reset it; a successful server contact (authoritative time) repairs a high-water mark left by a one-off clock glitch.
43. **Dev keys**: a debug-only keyring file compiled behind `__DEBUG_KEYS__`, flagged `dev:true` and refused at run time by release builds; `scripts/release-gate.sh` fails a release with no/dev/malformed production keys or a bundle containing the dev keyring (proved by tests that build both ways).
44. **Windows CI naming**: electron-builder emits space-free file names (keeps `latest.yml`/auto-update valid); the workflow copies them to "Lighting Survey Reader Setup.exe" and "Lighting Survey Reader.exe". Preview builds (debug keyring) are labelled `windows-PREVIEW-not-for-customers`.
45. **Reading provider is a server setting (Anthropic or Groq).** Chosen and keyed in the License Manager (or env). Keys are saved encrypted (AES-256-GCM, key derived from the receipt key file), never returned by the API, audited by field name. The app is unchanged and still never holds any API key. A bring-your-own-key option inside the customer app was *not* built: it would move the key onto customer PCs and bypass the server-side licence check on page reads. Groq is implemented against its OpenAI-compatible API and tested against a stub only (docs were not reachable from the build environment); model ids are editable and "Test connection" lists the models a key can use.
